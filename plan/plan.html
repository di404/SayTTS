怎样判断一句话说完？

 测试音频是合成的干净语音，经 WAV 送进 app。真麦克风、真按键还没有测过。

定稿文字立即流式送 TTS，app 边收音频边播放。

填 16000 返回 400。 默认值会在服务端存档，首包多等约 3 秒。 默认用 gemini-3.8-flash-lite-tts，设置里可以换成 gemini-3.8-flash-tts。连接空闲 1 分钟后首包会慢约 0.4 秒，所以主播一开口，app 就先预热连接。

一个 TTS 请求 2 秒没有音频，app 就补发一个请求。

key 无效、参数错、限流时，重发也一样。 每发一个请求都重新计时。 经代理实测，请求偶尔 5–15 秒才有响应、返回 503，或有响应后一直没有音频。新建的连接上也一样。从本机分不清问题在代理还是在 Google。约 30 句自测里补发了 2 次。补发的请求也占每日请求数。

一句攒够 300 毫秒音频才开始播，句子中间不断音。

首块之后有时停 0.2–0.5 秒才来下一块。先攒够再播，停顿落在开口之前。 后一句一直在合成，音频先存着。

转写连接被服务关闭时，app 立即重连，只在两句之间换连接。

提前约 50 秒到达。 没定稿的句子在新连接上整句重发。

字幕在这句第一个有声采样播出时显示，播完 1.5 秒后隐藏，按“停止朗读”或“停止”时清空。句子编号里带着第几次开始，所以换设置重启后，上一次晚到的消息不会显示出来。

推理全部在云端，每小时直播约花 0.45 美元。

每日请求数 付费层级 1 的 gemini-3.8-flash-lite-tts 每天只能发 100 个请求（429 返回的原文）。一句话一个请求，补发的请求也可能计数。一场直播要几百句，所以要更高的层级。各层级的确切数字只在登录后的 aistudio.google.com/rate-limit 上，每天太平洋时间 0 点清零。

Gemini API key 放在哪里？

 补发的请求通常在出声前取消，多付的钱应该很少，但没有核对过账单。

共享：一个 Rust 工作区，界面是普通网页。

界面用系统自带的网页引擎：macOS 是 WebKit，Windows 是 WebView2。窗口被挡住或隐藏时，WebKit 默认几秒后就暂停页面；app 设为只降速、不暂停，所以列表一直跟得上。 所有请求走系统代理，设置里也可以另填一个。本次全部经 127.0.0.1:7890 实测。key 存在系统钥匙串里；没有填时，用环境变量 GEMINI_API_KEY。

不做：本地模型、实时变声、自动回话、自定义声音。

  • 本机不跑任何模型。转写和朗读都走 Gemini API。
  • 不改主播的原声。角色只朗读识别出的文字。
  • 角色不自己回答。实测用 Live 对话模型照读，12 句里有 1 句没有照读，上下文还越积越长。
  • 不做声音设计和声音复刻，只用 30 种预置声音。
  • 不用 Google Cloud TTS 和 Chirp 3。它们要服务账号认证，不能只用 API key。

将来：监听外放时用回声消除，取代“外放时暂停收音”。

  • 现状：监听用外放时，麦克风会收进朗读的声音，转写后再读一遍。设置里的“外放时暂停收音”是半双工：监听出声期间（含播完后 300 ms）不收音，正在说的一句立刻收尾。代价是这段时间说的话会丢，所以做成可选，默认关。
  • 目标：边听边说也不丢话。用监听实际播出的音频当参考信号，从麦克风输入里减掉回声，再送去断句和转写。
  • 要先确认：用哪个实现（WebRTC AEC3 的 Rust 绑定或纯 Rust 移植，或 macOS 的 Voice Processing IO），能否在本机编译；麦克风和外放是两个设备时的时钟漂移和延迟对齐。
  • 做好后，“外放时暂停收音”可以去掉或保留为兜底。
